# ربات مدیریت دانش‌آموزان بله

پایتون ۳.۱۱ به بالا، PostgreSQL، رابط فارسی داخل ربات و دریافت پیام با Long Polling. پنل وب لازم نیست. شناسه پیش‌فرض مدیر `1891614962` است؛ دسترسی بر اساس `from.id` و فقط در گفت‌وگوی خصوصی بررسی می‌شود.

## انتخاب دیتابیس لوکال یا اصلی

بات روی سیستم شخصی با هر دو دیتابیس قابل اجراست؛ اتصال هم‌زمان یا همگام‌سازی دو دیتابیس انجام نمی‌شود. در `.env` این مقادیر را تنظیم کنید:

```dotenv
DATABASE_TARGET=local
LOCAL_DATABASE_URL=postgresql+psycopg://bale:YOUR_PASSWORD@127.0.0.1:5432/bale_school
MAIN_DATABASE_URL=postgresql+psycopg://USER:PASSWORD@HOST:5432/DATABASE?sslmode=require
```

برای دیتابیس اصلی، `DATABASE_TARGET=main` بگذارید؛ برای تنظیمات قدیمی، `DATABASE_TARGET=default` از `DATABASE_URL` استفاده می‌کند. رمزهای دارای کاراکتر رزروشده باید URL-encode شوند. مقدار انتخاب‌شده اگر خالی باشد خطا می‌دهد و به دیتابیس دیگر برنمی‌گردد.

برای راه‌اندازی PostgreSQL لوکال بدون نصب مستقیم (Docker Desktop باید در حال اجرا باشد):

```powershell
docker compose -f compose.yaml -f compose.local.yaml up -d db
.\.venv\Scripts\python tarhhadibot.py
```

رمز `LOCAL_DATABASE_URL` باید همان `POSTGRES_PASSWORD` در `.env` باشد. پورت فقط روی `127.0.0.1` باز است؛ اگر ۵۴۳۲ اشغال است `LOCAL_POSTGRES_PORT=5433` بگذارید و پورت URL را هم تغییر دهید. تغییر رمز در `.env` رمز دیتابیس موجود در volume را تغییر نمی‌دهد.

برای اجرای خود بات در Docker با دیتابیس اصلی و بدون ایجاد دیتابیس جدید:

```powershell
docker compose -f compose.main.yaml up -d --build
```

برای اتصال به دیتابیس اصلی از سیستم شخصی، دسترسی شبکه/VPN و مجوز اتصال PostgreSQL لازم است. قبل از آزمایش از دیتابیس اصلی پشتیبان بگیرید؛ تغییرات واقعاً روی آن ثبت می‌شوند. برای آزمایش لوکال از توکن بات جدا استفاده کنید؛ یک توکن را هم‌زمان در دو محیط اجرا نکنید. این تنظیمات داده‌ها را منتقل نمی‌کنند و فقط جداول مخصوص بات را در دیتابیس مقصد ایجاد می‌کنند؛ اتصال به جداول سامانه‌ای دیگر نیازمند تطبیق ساختار است.

## حضور و غیاب داخل بات

- مدیر: «کلاس‌ها» ← انتخاب کلاس ← «ثبت حضور و غیاب داخل بات»؛ برای هر دانش‌آموز «حاضر» یا «غایب» را انتخاب و خلاصه را تأیید کنید. تاریخ مربوط به روز شروع ثبت به وقت تهران است. اکسل هم همچنان قابل استفاده است.
- پس از تأیید، هم حضور و هم غیبت به حساب متصل دانش‌آموز در خود بات ارسال می‌شود؛ پیامک ارسال نمی‌شود. دانش‌آموز باید قبلاً بات را شروع و حسابش را متصل کرده باشد.
- دانش‌آموز با «حضور و غیاب من» آخرین ۳۰ رکورد شخصی را می‌بیند. ثبت مجدد وضعیت یکسان اعلان تکراری نمی‌فرستد؛ تغییر وضعیت اعلان جدید دارد.

## امنیت توکن

توکن ارسال‌شده در گفتگو را باطل و جایگزین کنید. توکن جدید فقط در `.env` یا متغیر محیطی تنظیم شود؛ در سورس، لاگ و فایل اکسل قرار نمی‌گیرد. این پروژه توکن قبلی را ذخیره یا استفاده نکرده است.

## اجرا با Docker Compose

1. `.env.example` را به `.env` کپی کنید و `BALE_BOT_TOKEN` را تنظیم کنید.
2. مقدار `POSTGRES_PASSWORD` را با رمز قوی جایگزین کنید. برای سادگی اتصال Compose از حروف لاتین و ارقام استفاده کنید؛ رمزهای دارای کاراکترهای رزروشده URL نیاز به URL-encoding دارند.
3. اجرا:

```sh
docker compose up -d --build
docker compose logs -f bot
```

دیتابیس روی پورت عمومی منتشر نمی‌شود و داده در volume نگهداری می‌شود. فقط یک نمونه از سرویس bot اجرا کنید. اجرای همزمان روی یک دیتابیس با advisory lock رد می‌شود. سرویس پس از خطای اتصال دیتابیس با سیاست restart بالا می‌آید.

## اجرای مستقیم

PostgreSQL نصب کنید، یک دیتابیس و کاربر با دسترسی ساخت جدول بسازید؛ سپس:

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

توکن جدید و `DATABASE_URL` را در `.env` وارد کنید، سپس:

```powershell
.\.venv\Scripts\python tarhhadibot.py
```

جدول‌های نسخه اول خودکار ایجاد می‌شوند. تغییر ساختار نسخه‌های آینده نیازمند migration و پشتیبان‌گیری است؛ `create_all` جدول موجود را تغییر نمی‌دهد. در لینوکس از Compose یا یک سرویس systemd با restart استفاده کنید. ربات هنگام شروع وب‌هوک قبلی را حذف می‌کند؛ آن را همزمان با مصرف‌کننده دیگری برای همین توکن اجرا نکنید. اتصال HTTPS خروجی به سرور بله لازم است و پورت ورودی نیاز نیست.

## گردش کار مدیر

- با حساب مالک `/start` بفرستید؛ منوی مدیریت نمایش داده می‌شود.
- «ایجاد کلاس» ← نام کلاس. در «کلاس‌ها» هر کلاس با تعداد اعضا و عملیات آن نمایش داده می‌شود؛ نام قابل ویرایش است و لیست صفحه‌بندی دارد.
- «نمونه کاربران» یا «لیست فعلی» ← تکمیل اکسل ← «بارگذاری کاربران» ← ارسال فایل ← تأیید ثبت.
- ستون کاربران: `نام و نام خانوادگی | کد ملی | شماره تماس`.
- «اکسل حضور و غیاب امروز» تاریخ همان روز تهران را در شیت مخفی ثبت می‌کند. پس از تکمیل وضعیت همه ردیف‌های موجود، از «بارگذاری حضور و غیاب» فایل را بفرستید. پیش‌نمایش تاریخ شمسی و شمار حاضر/غایب، قبل از تأیید نشان داده می‌شود. فایل روز گذشته نیز برای همان تاریخ ثبت می‌شود، نه روز آپلود؛ تاریخ آینده رد می‌شود.
- ستون حضور: `کد ملی | نام و نام خانوادگی | وضعیت (حاضر / غایب)`.
- «اکسل تخفیف‌ها» فهرست اعضا و کدهای موجود را می‌دهد. برای دانش‌آموزی که نمی‌خواهید کد ثبت کنید، ردیف خالی کد را حذف کنید؛ برای چند کد، ردیف را تکرار و کد را متفاوت کنید.
- ستون تخفیف: `کد ملی | نام و نام خانوادگی | کد تخفیف | توضیحات/عنوان دوره`.
- «پیام همگانی» یا «ارسال پیام به کلاس» ← ارسال متن/عکس/صوت/ویدئو/فایل ← تأیید شمار گیرندگان. هر پیام به صورت مستقل با copyMessage کپی می‌شود؛ آلبوم چندفایلی در این نسخه یک پیام واحد محسوب نمی‌شود و برای ارسال آن، رسانه‌ها را جداگانه انتخاب کنید.
- «تنظیم راه‌های ارتباطی» متن، شماره و لینک‌ها را بدون تغییر سورس ذخیره می‌کند.
- «مدیریت دانش‌آموز» با کد ملی: مشاهده، فعال/غیرفعال کردن و قطع اتصال حساب بله با تأیید. قطع اتصال برای تعویض حساب کاربرد دارد. «حذف عضویت» از داخل کلاس، سوابق را حذف نمی‌کند.
- «وضعیت ارسال‌ها» آمار کلی صف و امکان تلاش مجدد پیام‌های ناموفق را نشان می‌دهد؛ آمار هر کمپین جداگانه نیست.
- «لغو» یا `/cancel` هر عملیات نیمه‌تمام را لغو می‌کند؛ وضعیت‌ها پس از دو ساعت منقضی می‌شوند. دکمه تأیید قدیمی دوباره اجرا نمی‌شود.

## قواعد ثبت و اکسل

- فقط xlsx تولیدشده توسط همین ربات، همان نوع عملیات و همان کلاس پذیرفته می‌شود. نام شیت‌ها، ستون‌ها و شیت مخفی `_meta` را تغییر ندهید. اطلاعات مخفی امضای امنیتی نیستند؛ فقط مدیر قابل‌اعتماد اجازه بارگذاری دارد.
- کد ملی دقیقاً ۱۰ رقم است و ارقام فارسی/عربی تبدیل می‌شوند. بررسی checksum اعمال نمی‌شود تا مطابق نیاز، تطابق با رکورد فعال ملاک باشد. صفر ابتدایی کد ملی و تلفن باید با فرمت Text حفظ شود؛ صفر حذف‌شده به صورت خودکار حدس زده نمی‌شود.
- فایل دارای فرمول، ردیف تکراری، هویت نامطابق، وضعیت نامعتبر یا دانش‌آموز خارج از کلاس رد می‌شود؛ هیچ بخشی از فایل نامعتبر ثبت نمی‌شود.
- همه تغییرات پس از تأیید، در یک تراکنش انجام می‌شوند. واردکردن کاربران افزایشی/به‌روزرسانی است؛ حذف یک ردیف از اکسل، عضویت قبلی را حذف نمی‌کند. بارگذاری کاربران موجود، نام و شماره سراسری آن فرد را در تمام کلاس‌ها به‌روز و او را فعال می‌کند.
- حضور با کلید کلاس/دانش‌آموز/تاریخ یکتا است. بارگذاری مجدد وضعیت یکسان پیام تکراری تولید نمی‌کند؛ تغییر حاضر به غایب یا برعکس اعلان جدید دارد.
- تخفیف با کلید کلاس/دانش‌آموز/کد یکتا است؛ بارگذاری مجدد توضیحات را به‌روز می‌کند. حذف/انقضای تخفیف در محدوده این نسخه نیست.
- تاریخ اصلی حضور از نوع DATE و نسخه شمسی آن هم ذخیره می‌شود. زمان رویدادها UTC، محاسبه روز براساس `Asia/Tehran` و نمایش تاریخ شمسی است.
- سقف پیش‌فرض فایل ۵ مگابایت، ۱۰هزار ردیف و مجموع محتوای بازشده ۴۰ مگابایت است. محدودیت اول و دوم با env قابل تنظیم است.

## دانش‌آموز و حریم خصوصی

دانش‌آموز `/start` می‌فرستد و کد ملی رکورد فعال را وارد می‌کند. حساب بله به یک دانش‌آموز متصل می‌شود و اتصال ثبت‌شده توسط حساب دیگری قابل تصاحب نیست؛ مدیر می‌تواند آن را قطع کند. پیام حضور فقط برای دانش‌آموز فعال و متصل در زمان ثبت در صف قرار می‌گیرد. برای کاربران ثبت‌نام‌نکرده، پیام گذشته بعداً ارسال نمی‌شود. فقط فعالان متصل مخاطب پیام همگانی هستند.

**طبق نیاز فعلی، کد ملی تنها عامل اتصال اولیه است و اثبات مالکیت هویت نیست.** پیش از استفاده واقعی با اطلاعات حساس، تأیید شماره با OTP یا تأیید دستی مدیر را به محدوده پروژه اضافه کنید. هیچ شماره‌ای به صورت خودکار پیامک نمی‌شود. دسترسی دیتابیس و نسخه پشتیبان باید محدود باشد؛ رمزگذاری دیسک و سیاست نگهداری اطلاعات شخصی بر عهده مسئول استقرار است.

برای کاهش حدس‌زدن کد ملی، هر حساب حداکثر ۱۰ تلاش ورود در پنجره ۱۵ دقیقه‌ای دارد؛ `/start` محدودیت را پاک نمی‌کند. این محدودیت جایگزین احراز مالکیت شماره نیست.

## پایداری و محدودیت‌ها

آپدیت‌ها ابتدا در inbox ذخیره می‌شوند و سپس offset جلو می‌رود. ثبت داده‌ها و ایجاد outbox در یک تراکنش انجام می‌شود؛ آپدیت تکراری عملیات را دوباره اجرا نمی‌کند. پس از پنج شکست پردازش، رویداد ناموفق می‌شود و مدیر پیام هشدار می‌گیرد. جزئیات پیام و توکن لاگ نمی‌شوند. پیام‌ها بعد از restart از صف ادامه می‌یابند. ارسال‌ها تک‌پردازه‌اند؛ تنظیم فاصله `SEND_INTERVAL` و retry_after، نرخ را کنترل می‌کند و خطاهای موقت با backoff دوباره امتحان می‌شوند. عدد فاصله، تضمین سقف ثابت بله نیست؛ با محدودیت واقعی سرویس تنظیم شود. کدهای ۴۰۰/۴۰۱/۴۰۳/۴۰۴ ناموفق دائمی تلقی می‌شوند؛ تلاش مجدد دستی در منو وجود دارد.

تحویل API دقیقاً یک‌بار تضمین‌شدنی نیست: اگر بله پیام را دریافت کند ولی پاسخ شبکه از دست برود یا فرایند قبل از ثبت موفقیت قطع شود، retry می‌تواند پیام تکراری ایجاد کند. این محدودیت متفاوت از جلوگیری از ثبت تکراری حضور و غیاب است. وضعیت ارسال‌شده به معنی پذیرش API است نه خواندن کاربر. به علت محدودیت نگهداری آپدیت در خود بله، قطعی طولانی سرور می‌تواند رویداد ورودی را از دسترس خارج کند.

بدنه آپدیت‌های موفق و پیام‌های ارسال‌شده پس از پردازش پاک می‌شود؛ رکوردهای ارسال موفق قدیمی‌تر از ۳۰ روز و inbox موفق قدیمی به صورت دوره‌ای هرس می‌شوند. داده عملیات تأییدنشده پس از انقضای دو ساعت در هرس ساعتی پاک می‌شود. برای سیاست نگهداری بلندمدت، inbox/outbox ناموفق را نیز دوره‌ای بررسی و پاکسازی کنید. سوابق audit تغییرات مدیر و اتصال کاربران را نگه می‌دارد.

## آزمون

آزمون‌های خودکار بدون تماس با بله اجرا می‌شوند؛ SQLite فقط برای آزمون منطق است و اجرای واقعی فقط PostgreSQL را می‌پذیرد:

```sh
python -m unittest discover -s tests -v
```

برای اجرای همان آزمون‌ها روی PostgreSQL آزمایشی، `TEST_DATABASE_URL` را روی دیتابیس **خالی و اختصاصی تست** تنظیم کنید. آزمون جدول‌ها را قبل و بعد از هر تست حذف می‌کند؛ هرگز آدرس دیتابیس اصلی را وارد نکنید.

## پشتیبان‌گیری

پشتیبان روزانه و آزمون بازیابی ضروری است. در Compose:

```sh
docker compose exec -T db pg_dump -U bale -d bale_school --format=custom --file=/tmp/school.dump
docker compose cp db:/tmp/school.dump ./school.dump
```

فایل پشتیبان حاوی اطلاعات شخصی است؛ بیرون از سرور و با دسترسی محدود نگهداری شود. اجرای واقعی هنوز به توکن جدید، PostgreSQL و تست پذیرش در بله نیاز دارد.

مرجع ارتباط با بله: `https://docs.bale.ai/`؛ متدهای getUpdates، deleteWebhook، sendMessage، sendDocument، getFile، copyMessage و answerCallbackQuery.
